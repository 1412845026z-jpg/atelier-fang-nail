## 1. 依赖白名单（v5 版，取代 `v4-execute.md` 第 1A 节）

| 用途 | 允许 |
|---|---|
| 页面 | React、React DOM |
| 动效 | GSAP（含 ScrollTrigger、Draggable、InertiaPlugin、Flip）、Lenis |
| 视觉效果（粒子、流体、光、着色器） | **优先用原生 WebGL / WebGL2**，自己写着色器。如果确实需要库，只能用轻量库（例如 OGL），并且必须**按需加载**，不能进首屏 |
| 声音 | **浏览器自带的 Web Audio API** + 几个很小的音频文件（每个 ≤ 30KB，优先 `.webm`/Opus，同时提供 `.mp3` 兜底）。**不引入音频库** |
| 构建 | Vite、TypeScript、Tailwind（现有的） |
| 开发工具（不进网站） | `sharp`、`ffmpeg-static`、Real-ESRGAN、`rembg`；录屏用 `@playwright/test`（devDependency） |

- **不要引入**：anime.js、tween.js（和 GSAP 重复）；ammo.js、Rapier（物理引擎，容易做出小游戏感）；Remotion、HyperFrames（做宣传视频用，不属于网站）。
- 如果要用 three.js：必须在交付报告里说明为什么原生 WebGL 和 OGL 做不到、增加了多少体积，而且只能按需加载。
- **体积预算**：首屏 JS（gzip）≤ 200KB；手机 4G 下 LCP ≤ 2.5s；中端安卓 ≥ 50fps，目标 60fps；手机 dpr 上限 1.5。

## 2. 所有阶段都要遵守的硬规则

- v5 第 7 节的硬规则（不做小游戏、零说明文字、不提 AI、オーダーメイド 只在设计卡之后出现、手机竖屏优先构图）。
- **信息必须是网页里真实的文字**：价格、时长、营业时间、地址、交通、取消规则、预约方式，都要是 HTML 文字，只是在视觉上融进片子里（比如"印在纸卡上"的效果，用真实文字加样式实现，不能做成图片或画在 canvas 上）。这样 Google 搜索、LINE 分享预览、读屏软件都能读到。店铺信息另外输出 JSON-LD（`NailSalon` 类型），数据从 `src/config.ts` 读取。
- 声音默认静音；右上角放一个极简的开关；打开后全程生效。

## 3. 第 1 阶段：创意方案和风格帧（不写网站代码）

### 3.1 调研
- 搜索真实的日本高端美甲沙龙、高端美妆品牌的官网和作品图（至少 8 个）。
- 记录每一个**借了什么**（光、留白、排版、季节感、质感、动效节奏……），只借气质和完成度，不复制任何画面、文案或创意。
- 输出：`docs/v5-concepts/research.md`（附链接和截图）。

### 3.2 三个创意方案
做 **3 个方向明显不同**的方案（A、B、C），不能是同一个想法换三种颜色。每个方案都要交：

1. **一句话概念**：例如"颜色像墨滴进和纸一样，晕开成指甲"（这只是举例，不要照用）。
2. **视觉语言**：手法（插画、抽象、光效、材质拼贴、3D 抽象造型……）、色板、字体、胶片层的设定（调色、颗粒、暗角），以及手怎么被象征化。
3. **6 张关键画面，手机（375 宽，竖构图）和电脑（1440 宽）各一版，共 12 张**：
   开场 → 花瓣落甲（「花びらが、指先に。」）→ 定番换款 → セルフデザイン → 设计卡 → 片尾（店铺信息、预约方式、注意事项）。
   画面里要有真实的排版位置：款名、价格、时长出现在哪里、长什么样。
4. **「啊」的瞬间**：这个方案里，甲面每次换款是怎么变的，用 3–4 张连续的画面表达。
5. **三档怎么区分**：定番和セルフデザイン 的入口，在画面上怎么一眼看出不同（不靠文字）。
6. **信息放在哪里**：价格、时长、店铺信息、取消规则、LINE 预约，分别出现在片子里的哪个实物上。
7. **声音**：用文字描述这个方案用哪几种声音（玻璃轻碰、纸、布……），以及在哪些时刻出现。
8. **风险**：这个方案最难做好的地方是什么，你打算怎么解决。

- 关键画面可以用图像模型生成，再加上排版合成；要求是**看起来就是最终网站的样子**，不是情绪板拼贴。
- 自检：把 12 张图缩小排在一起，3 个方案之间一眼就能看出差别；每个方案内部的 12 张属于同一个世界（光、颗粒、调色统一）。
- 输出：`docs/v5-concepts/A/`、`B/`、`C/`（图片 + `README.md`），以及一份总览 `docs/v5-concepts/README.md`：3 个方案并排对比，写出你推荐哪个、为什么。

提交并推送后，告诉用户："第 1 阶段完成，请和 Grok 选定一个方案"。**选定之前，不进入第 2 阶段。**

## 4. 第 2 阶段：动态样片（只做最关键的 20–30 秒）

> **2026-11-23 已选定方案 A。**开始动态样片之前，先按 `docs/v5-concepts/DECISION.md` 重出关键画面（手改为和纸「透かし」、光和色彩调整、セルフデザイン 帧重出），交付到 `docs/v5-concepts/A-r2/` 后**停下来等确认**。确认后再做下面的动态样片，并且样片必须达到 DECISION.md 里的同一套要求。

只用选定的方案，在浏览器里把**"开场 → 花瓣落甲 → 第一次定番换款"**真正做出来。这一段决定了整站的成败。

- 跑在单独的页面上（例如 `/motion-test.html`），不改正式首页。
- 必须是真实的交互：滚动或滑动驱动，跟手，60fps。
- 带声音（默认静音，开关可用）。
- 至少做出一次完整的"啊"的换款瞬间。
- 关键段落如果需要视频，先用占位视频或你自己能生成的素材，并写清楚哪一段需要用户在 Google Flow / 可灵生成：给出首尾帧和提示词，放在 `docs/v5-video-kit/`。

### 录屏
用 Playwright 录屏（自带视频录制功能），再用 `ffmpeg-static` 转成 mp4。

```bash
npm i -D @playwright/test && npx playwright install chromium
```

- 375 宽和 1440 宽各录一段，每段再分静音版和有声版（有声版用 ffmpeg 把音轨合进去，或者在交付说明里写明声音出现的时间点）。
- 同时记录性能：每秒帧数、首屏 JS 体积、LCP。

输出：`docs/v5-motion-test/`（录屏 mp4 + `README.md`）。

## 5. 第 3 阶段：完整制作

按 v5 第 2–6 节和选定的方案，把整站做成一支从头到尾的交互式广告片：

1. 开场 → 花瓣落甲 → 定番 → セルフデザイン（按 `docs/review-grok-v4-self-design.md`）→ 设计卡 → オーダーメイド（只在设计卡之后）→ 片尾的店铺信息。
2. 全站统一的胶片层（v5 第 3 节）：同一套调色、颗粒、暗角，覆盖所有图片、视频、合成元素和界面。
3. 界面只有两种存在方式：场景里的实物，或者极轻的排版文字。不允许出现胶囊按钮、轮播滑条、白底圆角卡片这类通用网页控件。
4. 转场用镜头运动和匹配剪辑，不用叠化。
5. 每一次换款都有一个"啊"的瞬间。
6. 删除不再需要的 v4 代码和素材（例如 `PhotorealHandCompositor`，以及新方案用不上的写实手部图），保持仓库干净。
